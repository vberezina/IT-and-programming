## Учебная задача

### 1. Формулировка задачи

Создайте проект «Справочник горячих клавиш» в отдельном каталоге с именем `hotkeys-reference`. Проект должен быть Git-репозиторием и содержать файл `README.md`, в котором описывается назначение справочника, перечисляются категории горячих клавиш, приводится таблица сочетаний клавиш и показывается пример настройки собственной комбинации.

В процессе работы необходимо:

- создать структуру проекта;
- подготовить файл `.gitignore`;
- оформить `README.md` с использованием возможностей Markdown;
- создать вспомогательный файл `docs/notes.md`;
- сделать не менее трёх коммитов;
- проверить историю коммитов командой `git log --oneline`.

Тема проекта не должна совпадать с уже выданными вариантами, поэтому используется собственная тема — справочник горячих клавиш для работы в редакторе кода.

### 2. Ожидаемый результат

В результате выполнения должен быть получен каталог `hotkeys-reference`, в котором находятся файлы Git-репозитория, `.gitignore`, `README.md` и `docs/notes.md`.

Файл `README.md` должен содержать:

- заголовок первого уровня с названием проекта;
- краткое описание проекта из 2–3 предложений;
- маркированный список категорий горячих клавиш;
- нумерованный список действий по использованию справочника;
- таблицу с примерами горячих клавиш;
- блок кода с примером настройки сочетания клавиш;
- ссылку на внешний ресурс;
- изображение или текстовую замену изображения.

Файл `docs/notes.md` должен содержать краткие заметки о ходе выполнения проекта.

В Git-истории должно быть не менее трёх коммитов:

1. добавление исходной структуры проекта;
2. наполнение файла `README.md`;
3. дополнение документации или исправление содержимого проекта.

После выполнения команды `git log --oneline` должна отображаться история коммитов с понятными сообщениями.

### 3. Пошаговое описание выполнения

1. Создайте каталог проекта и перейдите в него через терминал:

```bash
mkdir hotkeys-reference
cd hotkeys-reference
```

2. Откройте созданный каталог в Visual Studio Code:

```bash
code .
```

Если команда `code .` недоступна, откройте редактор вручную и выберите папку `hotkeys-reference`.

3. Инициализируйте Git-репозиторий:

```bash
git init
```

4. Создайте файл `.gitignore` и добавьте в него временные или служебные файлы, которые не должны попадать в репозиторий:

```gitignore
.DS_Store
tmp/
node_modules/
```

5. Создайте каталог `docs` и файл `docs/notes.md`. Добавьте в него временную заметку, например:

```markdown
# Заметки проекта

Здесь будут находиться пояснения по работе со справочником горячих клавиш.
```

6. Создайте файл `README.md` и добавьте в него только заголовок проекта:

```markdown
# Справочник горячих клавиш
```

7. Сохраните файлы и сделайте первый коммит, фиксирующий исходную структуру проекта:

```bash
git add .gitignore README.md docs/notes.md
git commit -m "Add initial project structure"
```

8. Наполните файл `README.md` основным содержимым. Добавьте краткое описание проекта:

```markdown
# Справочник горячих клавиш

Проект предназначен для хранения часто используемых горячих клавиш редактора кода. Он помогает быстро находить нужные сочетания клавиш и ускорять работу с файлами, текстом и терминалом.
```

9. Добавьте маркированный список категорий:

```markdown
## Категории

- Файлы и навигация
- Редактирование текста
- Поиск и замена
- Работа с терминалом
```

10. Добавьте нумерованный список с инструкцией по использованию справочника:

```markdown
## Как пользоваться справочником

1. Определите нужную категорию действий.
2. Найдите требуемое действие в таблице.
3. Проверьте указанное сочетание клавиш в редакторе кода.
```

11. Добавьте таблицу горячих клавиш. Таблица должна содержать не менее трёх строк:

```markdown
## Основные сочетания клавиш

| Действие | Сочетание клавиш | Категория |
| --- | --- | --- |
| Открыть файл | Ctrl + P | Файлы и навигация |
| Закомментировать строку | Ctrl + / | Редактирование текста |
| Открыть встроенный терминал | Ctrl + ` | Работа с терминалом |
```

12. Добавьте блок кода с примером собственной настройки горячих клавиш:

````markdown
## Пример настройки собственного сочетания

```json
{
  "key": "ctrl+alt+s",
  "command": "workbench.action.files.saveAll"
}
```
````

13. Добавьте ссылку на внешний ресурс:

```markdown
## Дополнительные материалы

Подробнее о горячих клавишах можно узнать в [документации Visual Studio Code](https://code.visualstudio.com/docs/getstarted/keybindings).
```

14. Добавьте изображение или его текстовую замену. Если изображение недоступно, используйте текстовую замену:

```markdown
## Схема справочника

![Схема справочника горячих клавиш](docs/scheme.png)
```

Или используйте текстовую замену изображения:

```markdown
Изображение недоступно. Схема справочника: категории → действия → сочетания клавиш.
```

15. Сохраните изменения в `README.md` и сделайте второй коммит:

```bash
git add README.md
git commit -m "Add README content"
```

16. Дополните файл `docs/notes.md` более подробными заметками. Например:

```markdown
# Заметки проекта

Проект содержит справочник горячих клавиш для работы в редакторе кода.

## Что сделано

- Создана структура проекта.
- Добавлен файл README.md.
- Подготовлены категории горячих клавиш.
- Добавлена таблица основных сочетаний.

## Возможные улучшения

- Расширить таблицу новыми командами.
- Добавить раздел с пользовательскими сочетаниями.
- Подготовить изображение схемы проекта.
```

17. Сохраните файл `docs/notes.md` и сделайте третий коммит:

```bash
git add docs/notes.md
git commit -m "Expand project notes"
```

18. Проверьте состояние репозитория:

```bash
git status
```

Если все изменения зафиксированы, в выводе должно быть сообщение о том, что рабочая директория чиста.

19. Проверьте историю коммитов:

```bash
git log --oneline
```

В истории должны отображаться минимум три коммита с понятными сообщениями.

20. Проверьте отображение Markdown в Visual Studio Code. Откройте файл `README.md` и используйте предварительный просмотр:

```text
Ctrl + Shift + V
```

В предварительном просмотре должны корректно отображаться заголовки, списки, таблица, блок кода, ссылка и изображение или его текстовая замена.
